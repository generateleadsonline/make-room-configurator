# Private enquiry, request and PDF gate

`POST /api/quote` takes `{config, lead, requestId, botField}`. `config` is a v2 design (see `src/catalog.js`) and must already be normalised: anything `normalizeConfig` would change (unknown keys, moved or overlapping openings, a finish the building type cannot have, a back-wall opening on an extension, off-step overhang or decking sizes) is refused with a `field` such as `openings`, `cladding` or `width`. Object key order does not matter. The lead is `{firstName, lastName, email, phone, postcode, timeline, budget, notes, marketing}`; the first five are required. `timeline` is `''` or one of `INSTALL_TIMES` and `budget` is `''` or one of `BUDGETS` (both in `src/validation.js`). Error `field` values are the input names, so the UI can focus the field by id. The receipt stores `phone` (national format, e.g. `07912 345678`) and `phoneE164`, plus `source` and `submittedAt`. It is an immutable record in strongly consistent Netlify Blobs. The function then issues a Secure, HttpOnly, SameSite=Lax session scoped to `/api`. A rejected or unconfirmed storage write never returns a price or a success response. Follow-up design revisions (`{config, requestId}` with the session cookie) need that saved session and cannot change the original receipt.

`POST /api/request` takes `{topic, firstName, lastName, phone, email, postcode, bestTime, preferredDate, notes, marketing, config?, requestId, botField}`. `topic` is `callback`, `visit` or `brochure`. Names and phone are always required. Email is required for `brochure` and is validated whenever it is given. Postcode is optional. `bestTime` is `''` or one of `BEST_TIMES`. `preferredDate` is `''` or a `YYYY-MM-DD` date from today (UTC) to 120 days ahead. An optional `config` goes through the same strict check as above. The endpoint is same-origin only, size-limited, protected by a honeypot and rate-limited at 10 a minute per IP. The record is written once to `requests/{requestId}`, and a replay of the same body returns the same `{saved: true, reference: 'MR-REQ-XXXXXXXX'}`. A changed replay returns 409. If a valid quote session cookie is present, the record also stores its `leadId`.

Phone rules (`normaliseUkPhone` in `src/validation.js`, shared by the browser and the server):
- **Accepted:** UK mobiles 071–075 and 077–079, Isle of Man 07624, geographic 01/02 numbers and 03 numbers. Spaces, dashes, dots, brackets and +44, 0044, 44 or "+44 (0)" prefixes are all fine.
- **Refused:** 070, 076, 08 and 09 numbers, Ofcom's drama and sample ranges (07700 900xxx, 01632 960xxx, 020 7946 0xxx and the rest) and numbers made of one repeated digit.

`POST /api/design-pack` accepts a complete PDF of up to 4 MB, and only for a design that belongs to the saved enquiry. `GET /api/design-pack?designReference=...` also needs that enquiry session. PDF and API responses are private and uncached. Production storage is `make-room-leads`, and deploy previews use an isolated store. No personal information or session tokens appear in function logs.

Planning estimates use Make Room's published size examples (January 2024 cost guide), interpolated by floor area from 7.5 to 24 m². Below 7.5 m² the estimate is the published £9,980 starting price. Above 24 m², and for every modular extension, the estimate is a specialist quote with a null total. Each bi-fold door adds the published minimum allowance of £3,500. Every other choice is listed as "Priced by your designer", so option prices are never guessed. Source links, scope and exclusions are returned with the saved quote. Set `MAKE_ROOM_PRICING_MODE=quote-only` to give specialist pricing on every request. All monetary calculations run on the server only.

The application stores enquiries and requests privately and does not send email or CRM messages. Set up any notification integration separately. Label the test records used for deployed QA clearly and remove them after verification. Review the retention policy and analytics consent before installing the prototype on the production company site.
